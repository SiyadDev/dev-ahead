## The top 3

### 1. Model choice became an effort dial on a metered budget, and top effort is mostly overspent

**ACT NOW** High confidence.

Copilot Fusion became generally available on 28 October. You choose an effort level (Standard, High or Max), not a model, and Fusion handles each prompt one of three ways: one model answers; a cheap model drafts and a check escalates to a stronger one; or one model critiques another's draft. You pay each model's standard rate. GitHub says Fusion Max scored within two points of Claude Code with Opus 5.5 Max on the Artificial Analysis Coding Agent Index, at about half the API cost per task. The same day, enterprise Copilot moved to usage metered from the first request against a budget, with no included allowance. Vercel's Virtual Models do the same at the gateway: agents call an alias such as `vmc/coding-agent` whose model you change in one place.

**Why it matters:** a Together AI paper the same week (below) found the highest effort cost up to 42 times the lowest on tasks every level solved, and often failed tasks that lower effort solved. Starting low and escalating only after a verified failure matched fixed top effort. AI cost is now a policy you write: a budget, a router and an escalation rule. Put an alias in front of every model call and default to low effort with a check. The half-cost figure is GitHub's own.

Sources: [GitHub, Copilot Fusion](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion), [GitHub, Enterprise includes Copilot](https://github.blog/changelog/2026-10-28-github-enterprise-now-includes-access-to-github-copilot), [Vercel, Virtual Models](https://vercel.com/changelog/virtual-models-now-available-on-ai-gateway)

### 2. 40% of pull requests start with an agent, and reviewers took the agent's side 86% of the time

**ACT NOW** High confidence.

GitHub's Octoverse report says that as of September developers start more than 40% of pull requests with an agent, up from 17% in March. The part fewer people will have read is Anthropic's 27 October study. Fifty professional analysts did a realistic causal analysis with Claude Code. On each of four judgement calls, a coin flip secretly set which option the agent would argue for. Analysts went with the agent's lean 86% of the time; 50% would mean it made no difference. Those who had already stated a preference abandoned it 60% of the time when the agent disagreed, and 6% when it agreed. 77% reused the agent's arguments; 15% credited it. Anthropic notes it strengthened the leans on purpose, so real effects may be smaller.

**Why it matters:** "a human reviews it" is the control most teams rely on, and it is weaker than it looks. Write down your call before you read the agent's case. GitHub Agentic Workflows, generally available the same day, is a good template: the agent is read-only by default, declares its writes as "safe outputs", and a separate job scans them before they apply.

Sources: [Anthropic, How AI agents shape experts' judgment calls](https://www.anthropic.com/research/agents-judgment-calls), [GitHub Octoverse 2026](https://github.blog/news-insights/octoverse/octoverse-commits-pushes-reach-new-highs-in-2026-as-developers-build-with-agents/), [GitHub, Agentic Workflows](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available)

### 3. Claude Code stops sending the safety event issue 4 recommended

**ACT NOW** High confidence.

2.1.312 says only: "Changed Claude Code to stop sending the `claude_code.safety_event` OpenTelemetry event." It arrived in 2.1.307, five releases earlier. The same release caps hooks at 24 running at once per session. 2.1.311 stops Claude Code retrying requests the API marked as not retryable, which in unattended retry mode could hold a turn indefinitely.

**Why it matters:** this is a correction to issue 4. A dashboard or alert built on that event is now silent, and silent looks the same as green. Search your dashboards for it. The harness is a dependency that changes every few days and doesn't always say why, so pin its version in CI and scheduled jobs, and read the changelog before you upgrade.

Source: [Claude Code CHANGELOG, 2.1.311 and 2.1.312](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

## Signal radar

### Repeat-safety is becoming a runtime feature

**WATCH** High confidence.

Issue 4: Claude Code retries HTTP MCP calls only for read-only or idempotent tools. Issue 5: a timed-out call tells the model not to repeat it. Now Cloudflare Computer v0.7.0 lets agent code resume after a deploy or crash by replaying it with recorded results, and warns that a call whose result wasn't recorded may run again "even if its action already succeeded". It adds `unsafeToRepeat()` and `ctx.interrupt()`, which pauses a run for approval. Expect "safe to run twice?" to become a declared property of every tool.

Sources: [Cloudflare, Computer v0.7.0](https://developers.cloudflare.com/changelog/post/2026-10-26-computer-durable-javascript/), [Claude Code 2.1.311](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

### Agents now edit the files that steer agents

**WATCH** Medium confidence.

Copilot Memory is generally available on paid plans. Copilot "dreaming", an opt-in preview, curates memories and opens pull requests that change your checked-in skills and instruction files. A University of Illinois paper, [Memory Tax](https://arxiv.org/abs/2610.34073), cautions that many dedicated memory systems do worse than plain retrieval over raw history, because reorganising history drops evidence. Review a curator's pull requests like code, and protect those files with CODEOWNERS.

Source: [GitHub, Memory and dreaming](https://github.blog/changelog/2026-10-28-github-intelligence-puts-your-code-context-and-history-to-work)

## Research frontier

### What effort level should I choose?

**ACT NOW** High confidence. Horizon: already shipping. Together AI.

[arXiv 2610.34491](https://arxiv.org/abs/2610.34491). The authors ran the same tasks at every effort level on proprietary and open-weight models, across four benchmarks including long agent tasks, and compared results task by task. They call effort a "credence good": you see the outcome, never whether the extra compute was needed. Higher effort raised overall accuracy but often failed tasks a lower level solved. On easy tasks it cost up to 42 times more. Starting at the lowest effort and escalating after a verified failure matched or beat fixed top effort, more cheaply for most proprietary models.

**Why it matters:** it's the case for cascades and against "always max". If your agent has a check, such as tests or a schema, you can use this today. Connects to **Model routing** on the Watch board; no status change.

### FeatureArc: coding agents on features that evolve

**WATCH** Medium confidence. Horizon: 12 months. Tencent.

[arXiv 2610.37434](https://arxiv.org/abs/2610.37434). 73 tasks built from real repository histories, where one feature is extended over 2 to 10 stages and each stage builds on the agent's own earlier code. Tests check both the new behaviour and the old. Ten agents worked in one session with no outside test feedback. Success fell from 62.7% on the first stage to 28.5% for the whole feature. Inherited defects appeared in 72.9% of failed later stages, and agents left the earlier error unnoticed about 95% of the time.

**Why it matters:** real work is the third extension of something an agent wrote last week. Between agent steps, re-run the tests for old behaviour, not only the new ones. Connects to **Autonomous QA**; no status change.

## Architecture & practice shifts

### Decide before you read the agent's case

**ACT NOW**

For any review that needs judgement (a metric choice, a migration approach, a security call), write down your call first, then read the agent's reasoning. In the Anthropic trial, people abandoned their own view ten times as often when the agent disagreed as when it agreed.

### The agent proposes, something else applies

**WATCH**

GitHub's safe outputs, Cloudflare's approval pauses and Vercel's host-and-sandbox split all follow one pattern. The agent proposes changes, and a separate component checks and applies them. Build unattended agents this way from the start.

## This week's experiment

Build an unattended agent whose only write is declared and checked. 60–75 minutes.

**Build:** in a throwaway GitHub repository with a small test suite, install the `gh aw` extension and write one agentic workflow in Markdown. When CI fails, the agent reads the logs and the diff, and its only permitted output is one comment on the pull request with a suspected cause and a fix. Break a test on purpose and push.

**Done when:**

1. The compiled workflow is committed and runs on the failing push.
2. The pull request gets exactly one comment, written through the safe output, and the run log shows the threat-detection job ran first.
3. You've asked the workflow to push a commit and seen it refused, because that isn't a declared output.
4. You've written `gh aw forecast`'s monthly range next to what the run actually cost.
5. One line says what check you'd add before trusting it on a real repository.
