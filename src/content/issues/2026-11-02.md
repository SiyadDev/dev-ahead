## The top 3

### 1. Agents follow your existing code over your instructions, and one in seventeen skills tells them not to ask

**ACT NOW** Medium confidence.

Three preprints looked at the files that steer coding agents. In 5,625 controlled trials across four agents, when existing code and the agent's own habits disagreed, agents copied the existing code 359 times in 360. Where examples sit matters more than how many there are: three supporting files nearby got 96% adoption, while files elsewhere got 4%. When a task asks for something different from the existing code, a written priority rule beat examples. In real open-source repositories, one rule loaded by the harness took joint success from 0 of 120 to 117 of 120.

The second scanned 1.53 million public skills. About one in seventeen tells the agent to go ahead without approval, use `--no-verify` or stop checking in, and open-source skill scanners caught at most 46% of these. The third planted malicious memory files: Claude Code named the file in about two-thirds of its final messages, while OpenCode mentioned it almost only in reasoning the developer doesn't read. Meanwhile Cloudflare's Agents SDK now lets an agent write its own skills as plain files, with no deploy step.

**Why it matters:** the files that steer your agents are a dependency most teams don't review. When existing code and new work disagree, write an explicit rule rather than hoping examples steer. Read every skill you install for lines that remove an approval step, and put `CLAUDE.md`, `AGENTS.md` and your skills folder under CODEOWNERS. These are small studies: trust the direction more than the numbers.

Sources: [Precedent or Intent? (arXiv)](https://arxiv.org/abs/2610.38244), [When Skills Tell Agents Not to Ask (arXiv)](https://arxiv.org/abs/2610.37734), [Security Impact of Coding Agent's Memory Files (arXiv)](https://arxiv.org/abs/2610.38521), [Cloudflare, Agent Skills are files](https://developers.cloudflare.com/changelog/post/2026-10-29-agent-skills-from-files/)

### 2. The harness, not just the model, decides what an AI security review finds

**ACT NOW** Medium confidence.

Snyk's VulnBench 2.0 has 108 hand-checked vulnerabilities that attackers can reach, in 20 real web apps. A tool gets credit only if it pins both where the attacker's input enters and the dangerous call it reaches. Snyk Code, a rule-based static scanner, found 89. Claude Code's `/security-review` with Opus 5 at xhigh effort found 85. They disagreed on 28, too few to call a winner. Together they found 101 of 108. The striking result: without Claude Code's built-in review policy, the same model found 16 instead of 9 of the 20 vulnerabilities in classes that policy excludes or limits.

**Why it matters:** "we ran an AI security review" means little until you say which harness ran it and what it excludes. Run a static scanner and an agent review together, and report what each found. Snyk sells static scanning and wrote this benchmark, so treat the head-to-head as Snyk's own figures. The finding that the two together beat either one is the part to rely on.

Source: [Snyk VulnBench 2.0 (arXiv)](https://arxiv.org/abs/2610.38617)

### 3. Anthropic ships a cost meter, and a paper finds splitting work across agents doesn't pay

**ACT NOW** High confidence.

This follows issue 6's top item. On 29 October Anthropic launched a Usage and Cost Analytics API in beta. It reports tokens and cost grouped by model, workspace, API key, and the user or service account behind each request. Claude Code 2.1.316 added pooled group budgets and `CLAUDE_CODE_SUBAGENT_EFFORT` for subagents. A paper measured the cost of splitting work across agents with Opus 5.5 and Haiku 5.5 on 135 coding tasks. A planner, coder and reviewer pipeline cost 3.22 times a single strong call, took 3.24 times as long, and solved no more tasks. The saving came from choosing one model per task: picking the right single call each time solved 94.3% at half the strong model's cost per solved task.

**Why it matters:** before you add agents to a pipeline, test it against one strong call and one cheap call on a few real tasks. Set subagents to lower effort now that there's a setting for it. You can now report cost per user or key from Anthropic's own API. The paper used small function-level tasks, so it doesn't settle long-running work.

Sources: [Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview), [Claude Code changelog, 2.1.316](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), [The Coordination Tax (arXiv)](https://arxiv.org/abs/2610.37700)

## Signal radar

### Deploys stop cutting off agents mid-task

**WATCH** High confidence.

Cloudflare's Durable Objects now defer code updates by default. When you deploy, an active object can keep running its old code for up to five minutes while it waits to go idle, and hibernated WebSockets stay connected. You can set the wait from zero to 24 hours. Before this, a deploy interrupted work in progress. It's the fourth issue running where a runtime takes on "don't do it twice, don't stop halfway". Check your deploy scripts don't assume new code is live at once.

Source: [Cloudflare, Durable Objects defer code updates](https://developers.cloudflare.com/changelog/post/2026-10-30-durable-objects-deferred-code-updates/)

### DeepSeek publishes a harness and an always-on repository agent

**WATCH** Medium confidence.

DeepSeek released `dsh-superagent-prototype`, labelled a research prototype and not an official product. It's a coding agent for one GitHub repository, packaged for "DeepSeek Harness". It opens a work item for each request, works in its own session and replies with a pull request. It acts only when someone asks or when a rule the team wrote allows it. An open-weight lab now ships its own harness, and its authorization document is a useful reference for unattended agents.

Source: [deepseek-ai/dsh-superagent-prototype](https://raw.githubusercontent.com/deepseek-ai/dsh-superagent-prototype/HEAD/README.md)

### "Train on it" and "answer with it" become separate switches

**WATCH** Medium confidence.

Vercel Firewall now handles AI crawlers (which collect pages for indexing and training) separately from AI assistants (which fetch a page to answer a user), on all plans. A day later OpenAI said it will honour a shared robots.txt signal for AI training preferences. (We read OpenAI's feed item.) For sites you build, "block AI" is now two decisions, and blocking assistants may cost visibility in answer engines.

Sources: [Vercel, AI crawlers and assistants](https://vercel.com/changelog/block-ai-crawlers-and-assistants-independently-with-managed-rules), [OpenAI, AI training preferences](https://openai.com/index/helping-websites-express-ai-training-preferences)

## Research frontier

### When Skills Tell Agents Not to Ask

**WATCH** Medium confidence. Horizon: 12 months. Institution not stated on the abstract page.

[arXiv 2610.37734](https://arxiv.org/abs/2610.37734). The authors hand-labelled 2,097 lines from skills for whether they loosen or tighten human oversight, then trained a detector to label all 1.53 million skills. 2.4% of skill families account for half of all copies. A general-purpose model given the authors' labelling guide caught 61% of these lines, against at most 46% for existing scanners.

**Why it matters:** skill review needs its own question ("does this remove an approval step?"), not only malware scanning. Expect registries to start flagging these lines within a year. It connects to **Portable skills** on the board; a study isn't an incident, so no status change.

## New capabilities to adopt

### Two Claude Code settings worth adding today

**ACT NOW**

`CLAUDE_CODE_SUBAGENT_EFFORT` (2.1.316) sets the effort subagents run at. `permissions.blockWritesOutsideWorkingDirectories` (2.1.314) makes Write and Edit refuse paths outside the working directories in every permission mode. About 10 minutes. Also: fast mode on Opus 4.8 is removed on 30 November, after which those requests return an error.

### Anthropic Usage and Cost Analytics API

**ACT NOW**

New `/v1/organizations/analytics/usage` and `/cost` endpoints (beta header `analytics-usage-cost-2026-08-24`) group usage and cost by model, workspace, API key and user. About 45 minutes for a script that posts a weekly table.

### Cloudflare Agents SDK: skills as files

**WATCH**

Put a folder with a SKILL.md in `/workspace/.agents/skills/` or an R2 bucket, and the agent uses it on its next turn; each skill is checked against the Agent Skills specification. It breaks code that used `agents/skills` directly. One to two hours if you already build on Workers.

## Architecture & practice shifts

### Write priority rules instead of relying on examples

**ACT NOW**

On Monday, open the `CLAUDE.md` or `AGENTS.md` of your busiest repository and add a short section saying which wins when existing code and the task disagree, for the patterns you're moving away from. Keep one good example where new code goes.

### Measure before you split work across agents

**ACT NOW**

Before building a multi-agent graph, run 10 to 20 real tasks as one strong call and one cheap call. Add a role only if it beats both.

## This week's experiment

Measure whether your instruction file actually steers your agent. 45–60 minutes.

**Build:** in a throwaway repository, write three files in `src/api/` that make HTTP calls with `axios`, and a `CLAUDE.md` that says nothing about HTTP. Run this task headless five times, resetting between runs: "Add `src/api/users.ts` with a `getUser(id)` function; use the built-in `fetch`." Count how often it uses fetch. Then add one rule to `CLAUDE.md`: "When existing code conflicts with the task's stated library, follow the task; new HTTP code uses fetch." Run five more. Finally, search your installed skills for lines like `--no-verify`, "without asking" or "skip confirmation".

**Done when:**

1. A table shows fetch against axios, five runs without the rule and five with it.
2. The rule's exact wording is committed.
3. Each skill search hit is marked keep, rewrite or remove.
4. One sentence says whether you'd trust the agent on a real repository with that rule in place.
