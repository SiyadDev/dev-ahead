A short window with one item that will break code if you ignore it. Anthropic's new API version came out on 21 October, but issue 4 couldn't find what it changed; the migration guide now says. Two Watch entries moved up a rung, both on vendor changelogs, including Cursor's, which confirms what issue 5 had to mark unverified.

## The top 3

### 1. Anthropic API version 2026-10-21 turns `temperature` into a 400 error

The Claude Platform release notes for 21 October ship the first Messages API version since `2023-06-01`, along with new SDK majors that send it by default: Python 2.0.0, TypeScript 1.0.0, Go 2.0.0, Java 3.0.0, C# 13.0.0, PHP 1.0.0, Ruby 2.0.0 and ant CLI 2.0.0. Under the new version, sending `temperature`, `top_p` or `top_k` returns a 400 error, even at the default value, and the parameters are gone from the SDK types. Document blocks inside assistant messages and citations on user-message text also become errors. `MessageParam` splits into one type per role, so in Python v2 you can no longer construct it directly, although plain dict messages still work. Admin API fields are renamed, and the SDKs move from MIT to Apache 2.0.

**Why it matters:** an unpinned dependency range or a routine `pip install -U anthropic` now breaks any call that sets temperature. On Claude 4.7 and later models, sampling already accepted only the defaults, so removing the parameter changes nothing there. On older models such as Sonnet 4.6, you lose low-temperature consistency, and the guide says nothing replaces it. Pin your SDK major today, then migrate on a branch. Claude Code's `/claude-api api-version` command (added in 2.1.307) handles the code changes.

Sources: [Claude Platform, Migrating to API version 2026-10-21](https://platform.claude.com/docs/en/api/migration-2026-10-21), [Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview)

### 2. Cloudflare Computer makes agent code resumable, with the call ID as the idempotency key

From v0.7.0 of `@cloudflare/computer`, an agent workspace for running code, setting `onInterrupt: "replay"` makes a run that was cut off by a deploy or crash start again from the beginning, reusing the recorded results of calls that finished. Cloudflare is explicit about the hard case: if a call's result wasn't recorded before the interruption, recovery may run it again even though it already succeeded. Operations that must not repeat can be marked with `unsafeToRepeat()`. A custom module function can also call `ctx.interrupt()` to pause the run until your application returns an approval. The changelog's example posts a GitHub comment only after approval, and passes `ctx.callId` as the idempotency key.

**Why it matters:** this is the third issue in a row about whether an agent's tool call may run twice. Issue 4 covered Claude Code retrying HTTP MCP calls only for read-only or idempotent tools, and issue 5 the error that tells the model not to repeat a timed-out call. Now an infrastructure SDK builds replay, a stable call ID and an approval pause into the runtime. Exactly-once side effects are becoming every agent tool's contract.

Source: [Cloudflare changelog, 26 October](https://developers.cloudflare.com/changelog/post/2026-10-26-computer-durable-javascript/)

### 3. GitHub makes model-judged permissions generally available in Copilot

Assisted permissions are now generally available in the Copilot CLI, the Copilot app and VS Code. When Copilot asks to run a command, access a path or open a URL, a language model evaluates the request: requests classified as clearly safe proceed, and the rest need your approval. Enterprise admins can block "Allow All" while keeping Assisted, and set the default mode for new sessions.

**Why it matters:** a model between the agent and your shell is now a policy-managed setting at a second major vendor, alongside Claude Code's auto mode. Permissions are settling into three tiers: automatic, model-judged, and a person. Pick your default, and list the actions (deploy, delete, publish, spend) that always go to a person.

Source: [GitHub changelog, 26 October](https://github.blog/changelog/2026-10-26-github-copilot-assisted-permissions-generally-available)

## Research frontier

### CoSA: skills that are safe alone can break policy together

**WATCH** Horizon: 12 months. ZODA, the Institute of Software (Chinese Academy of Sciences), UNSW and others.

[arXiv 2610.35082](https://arxiv.org/abs/2610.35082). Agent skills are usually vetted one at a time. This paper shows that combining them can still break policy: one skill's output gets reused by another without the restrictions it was produced under. Adding harmless-looking skills (at most 5% more) to an existing pool, without changing any existing skill or permission, raised policy violations from 35.0% to 58.5% across five models and three agent harnesses on 288 tasks. A simple information-flow check before consequential actions cut violations on one task family from 65.3% to 6.7%.

**Why it matters:** issue 5 predicted skill supply-chain trouble before the foundation's security guidance lands; this is the first measurement. Vetting each skill isn't enough: before an agent sends, pays or writes to production, check where each input came from. Supports the **Portable skills** entry.

### Simple harnesses beat hand-crafted agent pipelines at root-cause analysis

**WATCH** Horizon: already shipping. Peking University.

[arXiv 2610.35767](https://arxiv.org/abs/2610.35767). The authors compared five published root-cause-analysis agents for microservice failures, built from fixed stages and role agents, with three harnesses that prescribe none of the model's steps: one call over an evidence bundle, a SQL agent, and the Codex coding agent. On 90 validated incidents across six models, the simple harnesses named the right root cause first 65–77% of the time; the hand-crafted agents managed 16–53%.

**Why it matters:** hard-coded investigation steps skip the evidence you didn't anticipate. Before shipping a fixed-stage agent graph, compare it with one loop over the same tools on ten real cases. Supports the **Agentic coding** entry.

### Trial by Trace: grading the harness, not the model

**WATCH** Horizon: 12 months. TraceLite AI, the Institute of Automation (Chinese Academy of Sciences) and Tsinghua University.

[arXiv 2610.32285](https://arxiv.org/abs/2610.32285). This benchmark scores agent harnesses such as Claude Code, Codex and OpenClaw separately from task success, using each run's trace across 95 tasks. Over 3,420 runs with nine models, harness scores ranged from 59.8% to 72.0%. In 31.1% of runs the task succeeded even though the harness broke at least one of its own rules.

**Why it matters:** a passing result doesn't mean the agent behaved. For unattended runs, also assert on the trace: sandbox respected, approval requested, no unsafe retry. Supports the **Agent audit trail** entry.

*Papers were found through the arXiv API and Hugging Face Daily Papers and read on their arXiv pages; all figures are the authors' own.*

## New capabilities to adopt

### Pin the Anthropic SDK, then migrate on a branch

**ACT NOW**

Pin your current major (`anthropic<2`, or your current `@anthropic-ai/sdk` major) in every project. On a branch, search for `temperature`, `top_p`, `top_k` and direct `MessageParam(` calls, upgrade, and run your tests. About 10 minutes to pin and 30–60 minutes per codebase to migrate. ### Upgrade Claude Code to 2.1.311 and recheck your hook metrics

**ACT NOW**

`SubagentStop` hooks fired about twice a minute for each running subagent instead of once, so anything that counts or bills on that hook over-counted. 2.1.311 also stops retrying requests the API marked not retryable, which could stall unattended runs. About 10 minutes.

Source: [Claude Code CHANGELOG, 2.1.311](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

**WATCH**

## Practice shifts

### Give every side-effecting tool a call ID and a repeat policy

**ACT NOW**

List the tools your agents call that change state. For each, derive an idempotency key from a stable call ID or mark it unsafe to repeat. Three runtimes now act on exactly that, so leaving it unset is a choice.

### Prescribe the gates, not the reasoning

**WATCH**

Put an agent graph's fixed nodes where approval, authorization or hand-off happens, and let the model choose its steps in between.

## This week's experiment

Build a tool runner that survives being killed mid-run. 60–90 minutes, any language.

**Build:** a small tool runner with three tools: `read` (safe to repeat), `append` (writes a line, keyed by call ID), and `publish` (waits for a manual approval, then writes). Journal each completed call's result by call ID. Run read, append, publish, append; kill the process while it waits on approval; restart in replay mode, which re-runs from the top and returns journalled results instead of executing again. On Cloudflare, `@cloudflare/computer` 0.7.0 gives you these pieces ready-made.

**Done when:**

1. After the kill, restart and approval, the output file holds exactly two appends and one publish.
2. A keyless counter increment is marked unsafe to repeat, and you've decided what replay does with it.
3. A rejected approval shows up as an error, not a silent skip.
4. A five-line README states which tools get a key and which are marked unsafe.
