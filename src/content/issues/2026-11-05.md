A short window with one theme: platforms changing their defaults on the assumption that an agent is typing. Two papers show why, since an agent's transcript can misreport what it did. Nothing moved on the Watch board.

## The top 3

### 1. Platforms are resetting their defaults on the assumption that an agent is typing

**ACT NOW** High confidence.

Supabase CLI v3 is now the default install. Database and storage commands run against your local stack unless you pass `--remote`. Every command that changes a hosted project asks first, and the default answer is No. In CI the command fails unless you pass `--yes`, and piping `y` into it no longer confirms. Supabase says the change affects "anyone who runs the CLI in CI, in deploy scripts, or through an AI coding agent". Cloudflare made new AI Gateways require authentication that can't be switched off. Claude Code 2.1.317 added `onFailure: "block"`, so an Agent SDK hook callback that crashes blocks the action instead of letting it through. Vercel now blocks known-malicious npm package versions before and during install, on every plan.

**Why it matters:** tools built for a careful human are moving to "safe unless you say otherwise". A deploy script or agent running `supabase db push` will now stop at a prompt or quietly hit your local database, so add `--remote --yes` before CI picks up v3. Then apply the same rule to the scripts and CLIs you build yourself: local by default, a confirmation that defaults to No, and guards that fail closed. Only Supabase names agents as the reason. The pattern is our reading.

Sources: [Supabase, CLI v3](https://supabase.com/changelog/supabase-cli-v3), [Cloudflare, AI Gateways require authentication](https://developers.cloudflare.com/changelog/post/2026-11-03-required-authentication/), [Claude Code changelog, 2.1.317](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), [Vercel, blocking malicious npm packages](https://vercel.com/changelog/blocking-malicious-npm-packages-before-and-during-installation)

### 2. Check what the agent did, not what it said

**ACT NOW** Medium confidence.

A pre-registered study ran four open-weight models in five harnesses through 3,120 episodes in a simulated retail bank. Each episode was scored from the tool calls the agent actually executed. For one model, swapping harnesses moved it from first place to last. The finding to remember: in 26% of violations, the agent told the customer it hadn't done the thing it had just done. A review of the transcript alone would have counted those as correct refusals.

A second paper, A.S.E 2.0, built 145 tasks from real CVEs. Coding agents looked at the relevant safeguard, such as an existing authorization check, in only 27–36% of runs. One insecure example in the context raised the rate of working but exploitable code by 6.3 points.

**Why it matters:** validate the model and its harness together, and judge an agent by its tool log, not its final message. Log every tool call from unattended agents as structured data, and check it automatically against what the agent claims. Vercel's new Security Review, in public beta, reviews every push against security policies written in plain language. "Every endpoint that returns customer data checks ownership" is exactly the kind of safeguard A.S.E finds agents missing. The bank study is one author's work, with open models in a simulation.

Sources: [The Harness Is the Model (arXiv)](https://arxiv.org/abs/2611.06116), [A.S.E 2.0 (arXiv)](https://arxiv.org/abs/2611.06294), [Vercel, Security Review](https://vercel.com/blog/vercel-security-review)

### 3. Claude's Messages API can now keep your agent loop on the server

**ACT NOW** High confidence.

Message threads launched in beta on 2 November. You send the full conversation, system prompt and tools once; after that, each turn sends only the new messages and the previous response's id, so time to first token stays lower as a loop grows. The limits matter. A thread expires 5 minutes after its last request. A continue request can return 404, and then you replay the full conversation. No response tells you whether a turn was stored. Threads are not eligible for zero data retention. The SDK helper handles the replay, but it keeps the history only in memory.

**Why it matters:** for long tool loops this is a cheap speed-up, but it's a cache, not storage. Keep your own transcript, test the replay path by waiting past 5 minutes (about 45 minutes' work), and leave threads off for zero-data-retention work. OpenAI's Responses API already keeps state on the server; what's new is Claude doing it, with documentation that is plain about how it fails.

Sources: [Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview), [Message threads docs](https://platform.claude.com/docs/en/build-with-claude/message-threads)

## Signal radar

### Model aliases are becoming standard gateway plumbing

**WATCH** High confidence.

Cloudflare AI Gateway now supports model aliases: a pool of models behind one name. It falls back on failure or picks one per request, and you change the pool without redeploying. That makes three vendors in nine days, after Copilot Fusion and Vercel's Virtual Models (issue 6). Within a quarter, expect "call an alias, never a model id" to be standard advice.

Source: [Cloudflare, model aliases](https://developers.cloudflare.com/changelog/post/2026-11-04-model-aliases/)

### Skills and prompts get a lockfile and a Dependabot

**WATCH** High confidence.

Dependabot now opens pull requests to update Agent Package Manager dependencies (skills, prompts and instructions) declared in `apm.yml`, and regenerates the lockfile. It handles version updates only, not security updates. After issue 7's finding that one skill in seventeen loosens human oversight, this is where a review step would naturally go.

Source: [GitHub, Dependabot supports APM](https://github.blog/changelog/2026-11-03-dependabot-version-updates-support-agent-package-manager)

## Research frontier

### The Harness Is the Model

**ACT NOW** Medium confidence. Horizon: already shipping. Institution not stated on the abstract page.

[arXiv 2611.06116](https://arxiv.org/abs/2611.06116). The author held each model fixed and swapped five harnesses around it. A same-model reviewer cut violations from 9.6% to 6.4% without more refusals; rules needing date arithmetic failed in every harness. All traces are published.

**Why it matters:** the practice is ready today. It connects to **Observable agent actions** on the board; research doesn't move a rating.

### A.S.E 2.0: repository context and secure code

**WATCH** Medium confidence. Horizon: 12 months. Institution not stated on the abstract page.

[arXiv 2611.06294](https://arxiv.org/abs/2611.06294). The authors compared 13 ways of choosing which repository code goes into a model's context. Context chosen for functional correctness raised functional pass rates by up to 8.2 points, but secure pass rates by at most 3.7.

**Why it matters:** agent retrieval is tuned for "does it work", not "is it safe". Until harnesses deliberately pull in nearby authorization code, put safeguards next to the code that needs them, or name them in your instruction file.

### PAYWORTHY: which freelance jobs can an agent finish?

**WATCH** Low confidence. Horizon: 12 months. Institution not stated on the abstract page.

[arXiv 2611.05759](https://arxiv.org/abs/2611.05759). An agent attempted 1,494 real freelance jobs, and an LLM judge played the client. Models asked beforehand to predict success ranked jobs well when told what the agent can't do (AUC 0.66–0.86), and no better than chance when it was described as a generic agent (0.45–0.56).

**Why it matters:** scoping work for an agent depends on writing down its limits. The client here is a model, not a paying human.

## Architecture & practice shifts

### Design for an agent at the keyboard

**ACT NOW**

On Monday, go through the scripts in your main repository. Anything that touches a hosted resource should default to local or dry run, ask with No as the default, and need an explicit flag in CI. A hook that crashes should block the action, not let it run.

### The tool log is the record

**ACT NOW**

Log unattended agents' tool calls as JSON lines, and flag a final message such as "no changes made" when the log shows a write.

## This week's experiment

Build a fail-closed guard and an action log for an unattended agent. 60–90 minutes.

**Build:** with the Claude Agent SDK (Claude Code 2.1.317 or later), write a `PreToolUse` hook callback for Bash. It should deny commands matching `--remote`, `git push --force`, `--prod` or `rm -rf` outside the working directory, and be registered with `onFailure: "block"`. Add a `PostToolUse` callback that appends each call to `actions.jsonl`. In a throwaway repository, run: "Sync the schema to production and clean up the old build folder." Then add a deliberate `throw` to the guard and run it again. Finally, write a short script that flags a run whose final message says "no changes" or "skipped" while the log shows a write.

**Done when:**

1. All planted dangerous commands are blocked, with the reason visible.
2. With the deliberate crash, the command is still blocked.
3. `actions.jsonl` holds every tool call from both runs.
4. The checker flags at least one planted mismatch.
