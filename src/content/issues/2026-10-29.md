A busy window, mostly from one stage. GitHub Universe on 28 October made model routing, agent workflows and agent memory generally available, and the Octoverse report measured how far agents have spread. The launch list matters less than the pattern: routing, CI and instruction files are being redesigned around agents writing the first draft.

## The top 3

### 1. Model choice becomes a policy, not a pick

**ACT NOW** High confidence.

GitHub Copilot Fusion is now generally available. You don't choose a model; you choose an effort level (Standard, High or Max), and Fusion decides which models handle each prompt. It uses three patterns: one model answers directly; a cheap model drafts and a quality check decides whether to escalate ("cascade"); or one model drafts, another reviews and the first revises ("critique"). Admins choose which models it may use and can make it the default. You pay each model's normal rate for the calls it makes. By GitHub's own figures, Fusion Max scored 60 on the Artificial Analysis Coding Agent Index, within two points of Claude Code with Opus 5.5 Max, at about half the API cost per task. The same day, Vercel launched Virtual Models: a stable ID such as `vmc/coding-agent` whose model you change without redeploying.

**Why it matters:** "which model" is becoming configuration that changes weekly; Vercel counts 125 new models on its gateway in 90 days. The cascade is also what an independent paper this week found works best for reasoning effort (see Research frontier). If your agents hard-code one model at the highest effort, you pay for that on every easy task.

Sources: [GitHub changelog, Copilot Fusion](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion), [Vercel, Introducing Virtual Models on AI Gateway](https://vercel.com/blog/ai-gateway-virtual-models)

### 2. Agents become ordinary CI jobs, with guard rails built in

**ACT NOW** High confidence.

GitHub Agentic Workflows, an open-source project from GitHub Next, is generally available on Free, Team and Enterprise plans. You write the automation as a Markdown file and it compiles to standard Actions YAML, so it runs on your existing runners under your existing policies. You can use Copilot or bring another coding agent. The guard rails are the interesting part: agents get read-only permissions by default and run in a sandboxed container behind a firewall. Anything they want to change goes through a "safe outputs" step, and a separate threat-detection job scans proposed changes before they're applied. GitHub Next's prebuilt set includes a Daily Test Improver that adds tests to under-tested code. Separately, Vercel launched Vercel CI in beta because, it says, agents open more pull requests than CI keeps up with; it runs only the tasks a change affects.

**Why it matters:** the pattern to copy is the split between what an agent may read and what it may write: the agent proposes, a separate step validates, and only then does anything land. And if agents push to your repositories, CI is your next bottleneck.

Sources: [GitHub changelog, Agentic Workflows GA](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available), [GitHub Next agentics workflows](https://github.com/githubnext/agentics), [Vercel, Introducing Vercel CI](https://vercel.com/blog/introducing-vercel-ci)

### 3. More than 40% of pull requests now start with an agent

**WATCH** High confidence.

GitHub's Octoverse 2026 says that by September more than 40% of pull requests on GitHub started with an agent's first draft, up from 17% in March. That was 110 million in September alone. Agent-involved pull requests now merge within two weeks more often than others: 90% against about 86%, having trailed in February. 61% of Copilot users used more than one model. These are GitHub's figures and detection method.

**Why it matters:** on GitHub's numbers, whether agents can draft is settled; the work left is review, and reviewers accept agent drafts at least as often as human ones. A review process built for human-paced pull requests is now the part to redesign. This is adoption evidence, not evidence that the work is priced differently.

Source: [GitHub, Octoverse 2026](https://github.blog/news-insights/octoverse/octoverse-commits-pushes-reach-new-highs-in-2026-as-developers-build-with-agents/)

## Signal radar

### Human approval becomes a durable pause, not a blocking prompt

**WATCH** Medium confidence.

Cloudflare's `@cloudflare/computer` 0.7.0 lets an agent's code call `ctx.interrupt()` to wait for an approval. The wait survives deploys and crashes and doesn't count against the run's timeout. The changelog's own example passes `ctx.callId` as an idempotency key so a replayed call can't post twice. Approval becomes a pending record your app resolves later; expect other runtimes to copy it.

Source: [Cloudflare changelog, Computer durable JavaScript](https://developers.cloudflare.com/changelog/post/2026-10-26-computer-durable-javascript/)

### A vendor removed an agent safety event from its telemetry

**WATCH** Medium confidence.

Claude Code 2.1.312 stops sending the `claude_code.safety_event` OpenTelemetry event, added only in 2.1.307. The changelog gives no reason. The same release caps prompt and agent hooks at 24 running at once per session. Alerts built on that event will now look like silence, which is why an audit trail shouldn't depend on one vendor's event stream.

Source: [Claude Code CHANGELOG, 2.1.312](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

### Cursor's Origin marketplace, now confirmed

## Research frontier

### What effort level should you choose?

**ACT NOW** High confidence. Horizon: already shipping. Together AI.

[arXiv 2610.34491](https://arxiv.org/abs/2610.34491). Many models now take a "reasoning effort" setting. The authors call it a credence good: you see the result but never learn whether the extra thinking you paid for was needed. They measured it on proprietary and open-weight models across four benchmarks, including long agent tasks. Higher effort often failed tasks that lower effort had solved. On easy tasks every level solved, the top level cost up to 42 times as much as the lowest. A simple policy did better: start at the lowest effort and escalate only after a verified failure. It matched or beat fixed top effort everywhere, and cost less on most proprietary models.

**Why it matters:** this is the cascade pattern from Top 3 #1, applied to effort rather than models, and you can do it today with any API that exposes effort. It needs a cheap, automatic check of whether a step succeeded. Connects to the **Model routing** entry on the Watch board; no status change.

### Memory Tax: when agent memory does worse than search

**WATCH** Medium confidence. Horizon: 12 months. University of Illinois Urbana-Champaign.

[arXiv 2610.34073](https://arxiv.org/abs/2610.34073). Agent memory systems rewrite what an agent saw into notes, summaries or preferences. The authors compared many such systems against plain retrieval from the raw history (RAG) across several benchmarks and models, and found many memory systems did worse. They split memory's net value into a benefit and a "memory tax": evidence that gets lost or obscured when raw history is reorganised.

**Why it matters:** GitHub made Copilot Memory generally available this week and put "dreaming", which rewrites memories in the background, into preview. If you turn on agent memory, keep the raw history searchable too, and test a few known questions with memory on and off before you trust it.

### Hidden in Plain Sight: the instruction stacks of coding agents

**CONTEXT** Medium confidence. Horizon: already shipping. Federal University of Bahia and University of California, Irvine.

[arXiv 2610.37332](https://arxiv.org/abs/2610.37332). The authors captured the first model request from 1,886 releases of Claude Code, Codex, Gemini CLI, Qwen Code and OpenCode. What the agent sends is mostly not your prompt: tool definitions take 77.4% of Claude Code's latest request and 18.9% of Gemini CLI's. Instructions about permissions and risky operations are only 2–6% of the instruction text. Only 48% of the changes they traced came with a stated reason.

**Why it matters:** when an agent's behaviour changes after an upgrade, the cause may be a rewrite you never see. If you run agents in a pipeline, pin the version and log the request it sends, so you can tell a model change from a harness change. Connects to the **Harness layer** entry; no status change.

## New capabilities to adopt

### Wrap one recurring chore as an agentic workflow

**ACT NOW**

If you're on GitHub, pick one triage or report task and add it from the GitHub Next templates. Keep the default read-only permissions and see what the safe-outputs step allows through. About an hour for the first one.

Source: [GitHub changelog](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available)

### Put a model alias between your code and the model

**ACT NOW**

Whether you use Vercel's Virtual Models, another gateway, or a config value you own, stop putting model IDs in application code. Name each task (`triage`, `code-review`) and map it to a model in one place. About 30 minutes for a small service.

Source: [Vercel, Virtual Models](https://vercel.com/blog/ai-gateway-virtual-models)

## Disruption watch

No forecast came due. One entry moved up, and the rest held. The full board, with every entry's forecast and signs, is on the [Watch page](/watch).

- **Autonomous QA and test generation: Accelerating → Hitting the market.** It moved on its own pre-set sign, "GitHub or GitLab ship native test generation as generally available". Agentic Workflows (GA on 28 October) names test writing as a supported task, and GitHub Next ships a Daily Test Improver for it. It's a general agent runner, not a dedicated test feature, but the sign was written for this kind of GA. What to do differently: review agent-written tests by checking that each one fails when the code is broken.
- **Ultra-cheap and open-weight models**, Repricing the work, held. Its sign "a frontier lab cuts a price tier by 50% or more" was met: GPT-6.1 Terra is $1 / $5 per million tokens on OpenRouter, against $2 / $12 for GPT-5.6 Terra.
- **Model routing**, Accelerating, held. Copilot Fusion is the strongest evidence yet, but the next rung needs two major vendors with routing generally available, and the cost-study sign needs independent studies, not GitHub's own figure.
- **Agentic coding**, Hitting the market, held. Octoverse's 40% is adoption evidence. The next rung needs evidence that what clients pay has changed.
- **Observable agent actions**, Watching, held, with a counter-signal: Claude Code dropped its safety telemetry event.
- **AI-native infrastructure**, Hitting the market, held. Agentic Workflows run agents in a sandbox by default, which meets the entry's own sign. But the board's rules say a product feature can never move an entry to Repricing the work.
- Everything else held. The npm, CVE and Hacker News counts behind several signs couldn't be fetched this run: a gap in measurement, not a clean bill of health.

## Architecture & practice shifts

### Escalate on failure, don't start at the top

**ACT NOW**

On Monday, find the agent step where you set the strongest model or the highest effort "to be safe". Give it a cheap check (tests pass, the schema validates, the file exists). Run it at low effort and escalate only when the check fails. Log how often you escalate.

### Your instruction files now have more than one author

**WATCH**

GitHub's dreaming previews proposing edits to checked-in skills and instruction files through pull requests. Give those files an owner and review their diffs like code.

## This week's experiment

Measure what "highest effort" is costing you. 45–75 minutes.

**Build:** take one agent task you run often, such as fixing a failing test or writing a function to a spec. Pick ten real examples you can check automatically. Run each at the lowest effort level your model offers. Rerun at the highest level only the ones that fail the check. Then run all ten at the highest level for comparison.

**Done when:**

1. You have a table of the ten tasks with pass or fail and token cost for both policies.
2. You know the share of tasks the lowest level solved on its own.
3. You've counted any task that the highest level failed but the lowest level passed.
4. You've written one line saying which policy you'll use by default, and why.
