A busy window. Two frontier models shipped and the headlines covered them. This issue covers what sits underneath: your harness now matters more than the per-token price, small decision models carry a big share of production traffic, and agent loops are moving into durable server runtimes. Nothing moved on the Watch board.

## The top 3

### 1. Fable 5.2 is 20% cheaper per token, and your harness decides the rest of the bill

**ACT NOW** High confidence.

Claude Fable 5.2 costs $8 per million input tokens and $40 per million output tokens, down from $10 and $50 for Fable 5.1, and Claude Code 2.1.321 makes it the default Fable model. The release notes and the new prompting guide show where the bill and the breakages come from:

- **Edits to earlier turns fail.** If your code changes the system prompt, tools or an earlier message and then sends back a later thinking block, the request returns a 400 error, on every account.
- **Model switches work one way.** No other model reads Fable 5.2's thinking blocks, so a fallback to Opus 5.5 drops that reasoning.
- **Prompt lines move token use.** In Anthropic's testing, telling the model it owns the code raised output tokens by 70–80%, and it still refactored when a scope rule said not to. Text asking it to finish the whole task added about 30%.

**Why it matters:** a 20% cut per token can still mean a bigger bill. Latent Space reports that Artificial Analysis and SemiAnalysis both found Fable 5.2 uses more tokens than 5.1. Before you switch an agent, rerun an effort sweep on your own tasks and check whether your harness edits earlier turns. Delete inherited lines such as "never retry": the model treats any "never" as absolute.

Sources: [Claude Platform release notes, 9 November](https://platform.claude.com/docs/en/release-notes/overview), [Prompting Claude Fable 5.2](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2), [Claude Code changelog 2.1.321](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), [Latent Space (secondary)](https://latent.space/p/ainews-fable-5-2-retakes-world-1-llm-spot-as-ant-ipo-roadshow-begins/)

### 2. Decision models take a quarter of gateway requests for half a percent of spend

**ACT NOW** High confidence.

Decision models first appeared here in October as a repo pattern and one Microsoft model. Vercel's November AI Gateway Production Index shows how far they've spread: they handled 26% of gateway requests in October for 0.53% of spend. They classify, score or pick between options instead of generating text. Seven in ten teams running over 10 billion tokens a month used one. On 11 November Google's Gemini Decision 1 reached the gateway, so Google now sells one too.

The same report says models turn over fast. Over half of October's language-model requests went to models under 60 days old, and about half of teams running 10 million tokens a month changed their most-used model.

**Why it matters:** routing, policy checks, tool filtering and "is this done?" steps no longer need a large model. Put a decision model on them. And because models turn over every few weeks, keep each agent's model choice in config with an eval behind it. These are Vercel's figures from its own traffic.

Sources: [Vercel AI Gateway Production Index, November 2026](https://vercel.com/blog/ai-gateway-production-index-november-2026), [Gemini Decision 1 on AI Gateway](https://vercel.com/changelog/gemini-decision-1-now-available-on-ai-gateway), [Simon Willison on pricing (secondary)](https://simonwillison.net/2026/Nov/11/gemini-decisions-api/)

### 3. Coding-agent loops now run inside Durable Objects

**WATCH** Medium confidence.

On 9 November Cloudflare published three ways to run a coding-agent loop inside a Durable Object, a small stateful server with its own SQLite storage. An experimental Codex port compiles Codex's Rust turn code to WebAssembly and records every model call and tool run, so after a restart only interrupted steps run again. Nanocode, an independent project, runs Codex- and Claude Code-style agents the same way. Exo runs Markdown-defined agents with tools in Cloudflare Sandboxes. Separately, Vercel Sandbox snapshots now take under 0.4 seconds at the median, down from 4.4.

**Why it matters:** an hour-long agent no longer needs a laptop or a long-lived VM; it can live on a server that saves each step and resumes after a crash. The design rule is the one this newsletter has tracked for weeks: record every step, and make re-running an interrupted step safe. All three are early, so start with internal jobs.

Sources: [Codex agent loop on Workers](https://developers.cloudflare.com/changelog/post/2026-11-09-codex-harness/), [Nanocode in Durable Objects](https://developers.cloudflare.com/changelog/post/2026-11-09-nanocode-on-workers/), [Exo on Cloudflare](https://developers.cloudflare.com/changelog/post/2026-11-09-exo-on-cloudflare/), [Vercel Sandbox snapshots](https://vercel.com/changelog/vercel-sandbox-snapshot-creation-is-now-up-to-10x-faster)

## Signal radar

### "Rebuild any app" tools climb the star charts

**WATCH** Medium confidence.

Two of the fastest-rising repositories point agents at someone else's product. REA (+24k stars in seven days) gives an agent MCP tools to inspect binaries, Electron apps and websites without source code, then build a version of a feature. Craft Anything (+19k, created 31 October) has a coding agent build a "clean-room" copy of a site, app or game and scores how close it is. Stars are attention, not adoption. But if copying a feature gets this cheap, features stop being a moat, and value moves to data, integrations and support.

Sources: [REA README](https://raw.githubusercontent.com/morluto/rea/HEAD/README.md), [Craft Anything README](https://raw.githubusercontent.com/storytold/craft-anything/HEAD/README.md)

### Free-model plugins with a direct line to every install

**WATCH** Medium confidence.

`dsh-our-free-model`, a plugin for DeepSeek's harness, promises free, unlimited frontier models with no account or key. Its README says requests go through OpenCode's and Kilo's public gateways, and its maintainer can push announcements to every installed copy. Check where a free-model plugin sends your code before anyone on your team installs one.

Source: [dsh-our-free-model README](https://raw.githubusercontent.com/Ebony-Vinyl/dsh-our-free-model/HEAD/README.md)

## Research frontier

### Token spend measures use, not output

**ACT NOW** High confidence. Horizon: already shipping. JetBrains (study site).

The authors matched five weeks of coding-agent token use to the commits of 404 JetBrains engineers. In weeks with similar commit counts, the top tenth of spenders used 39 to 240 times more tokens than the bottom tenth, and an engineer who doubled their spend made only about 10% more commits. Most survey respondents also used agents for analysis, research and planning. Use token spend for budgeting, not as a productivity score.

Source: [The AI Era's Lines of Code? (arXiv)](https://arxiv.org/abs/2611.13396)

### Do agents follow your AGENTS.md?

**WATCH** Medium confidence. Horizon: 12 months. Affiliation not stated on the abstract page.

The authors turned each instruction in real agent context files (AGENTS.md, CLAUDE.md and similar) into a script that checks the agent's commits. Agents followed the guidance more often than not, but adherence split sharply: some instructions were always followed and some never, varying by instruction type and agent. Write each rule so a script can check it, and enforce the ignored ones with a hook or CI check.

Source: [Do They Do as They Are Told? (arXiv)](https://arxiv.org/abs/2611.13709)

### Turning repeated agent runs into plain code

**WATCH** Medium confidence. Horizon: 12 months. Affiliation not stated on the abstract page.

ReTrace reads a written procedure and a few logged agent runs, extracts the condition behind each step from the agent's own explanations, and compiles a workflow in which code, not a model, picks the next step. On 79 production procedures it finished 93.8% of tasks against the agent's 96.8%, at 24% lower cost (the authors' figures). For jobs you run hundreds of times, the agent becomes a way to write the workflow, not to run it.

Source: [ReTrace (arXiv)](https://arxiv.org/abs/2611.14492)

## New capabilities to adopt

### Claude Code 2.1.321 security fixes

**ACT NOW**

Fixes MCP sign-in sending refresh tokens to another host after a redirect, deny rules missing the file a `cp` or `mv` writes into a folder, and a read-only Bash command running outside the sandbox. One change to check: tool calls made by mods no longer prompt, even under your ask rules; only deny rules and policy stop them. Turn any ask rule you relied on into a deny rule. About 15 minutes.

Source: [Claude Code changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

### Dependabot alerts pause on inactive repos on 8 December

**ACT NOW**

Repositories with no push in a year lose Dependabot alerts (archived, not deleted). For old repos that still run in production, turn alerts back on in settings. About 20 minutes.

Source: [GitHub changelog](https://github.blog/changelog/2026-11-10-dependabot-alerts-will-pause-on-inactive-repositories)

### Supabase Correlated Logs (beta)

**ACT NOW**

Logs now link by `requestId`, `traceId` and `userId`, and the Supabase MCP server's `query_logs` tool accepts the same identifiers, so an agent can follow one failing request across services. About 30 minutes.

Source: [Supabase changelog](https://supabase.com/changelog/53230-correlated-logs)

## Architecture & practice shifts

### Treat a model as a dependency you'll replace

**ACT NOW**

One launch can change refusals, thinking-block rules and token use at once. Move each agent's model, effort and fallback order into config, and keep a few of your own tasks to rerun before each switch.

### Make every agent rule checkable

**WATCH**

Context files are followed unevenly, and models take "never" literally. For each rule in your AGENTS.md or CLAUDE.md, write the check that proves it held (a grep, a test, a hook), and move ignored rules into enforcement.

## This week's experiment

**Build:** a model-switch eval for one repository. Pick five recent tasks that a test or script can prove done. Write `eval.sh` to run each with `claude -p "<task>" --output-format json` on your current model, then on Fable 5.2 at `--effort medium` and `--effort high`, resetting the worktree between runs. Record pass or fail from your check, not the agent's message, plus cost and turns from the JSON, and whether each scripted context-file rule held.

**Done when:**

1. `eval.sh` prints a table: task × setting, with pass/fail, cost and turns.
2. Every pass is judged by a test or script.
3. You have a written choice of model and effort for that repo, with the numbers behind it.
4. The script is saved, so you can rerun it in one command when the next model ships.
