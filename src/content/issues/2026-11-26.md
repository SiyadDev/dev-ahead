A short window, three days. The headlines went to Gemini 4 Neon and AI maths proofs. Underneath: where your data goes, and what your agent loads, when nobody is watching. No entry on the Watch board moved.

## The top 3

### 1. Zero data retention becomes something you can check

**ACT NOW** High confidence.

On 23 November Anthropic launched Enterprise Frontier Safeguards (EFS) in beta. Claude's most capable models carry their own data-retention requirements, and EFS is how an eligible organisation gets zero data retention on them anyway:

- **No retained prompts:** Anthropic keeps no prompts or responses. Encrypted "Sealed Safety Data" goes to a bucket in your own cloud account, which your team can't read either.
- **Your reviewers:** Anthropic Human Review is always off, and your own people review the flagged Safety Cases.
- **Gaps:** it covers Messages API requests across a whole workspace. It doesn't cover code-execution containers, Files API uploads, Batch results or Managed Agents sessions.

The same day, Vercel launched Audited ZDR on its AI Gateway. A provider gets the label only after an independent security firm tests its claim against code, infrastructure and live traffic, then publishes the report. Three providers have begun audits, and no report is out yet. Vercel also runs canary audits: it plants unique URLs in prompts sent with retention turned off, so any request to one of those URLs shows that someone read the prompt.

**Why it matters:** "where does our code go?" used to get a link to a terms page. Now it can get a verified answer, so expect procurement teams to ask for one. Put sensitive traffic in its own workspace, and map which features each agent uses, because the ones EFS excludes are the ones agents rely on. Anthropic also set Claude Opus 4.5's API retirement for 22 January 2027.

Sources: [Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview), [EFS overview](https://platform.claude.com/docs/en/manage-claude/enterprise-frontier-safeguards/overview), [Vercel: Audited ZDR](https://vercel.com/blog/introducing-audited-zdr-on-ai-gateway), [Vercel: canary audits](https://vercel.com/changelog/ai-gateway-now-runs-canary-zdr-audits)

### 2. MCP servers can now ship skills, and a new hook can refuse their shell commands

**ACT NOW** High confidence.

Claude Code 2.1.331 and 2.1.332:

- **Skills from MCP servers (beta):** they appear as `server:skill` in the `/` menu.
- **A new gate:** a `PreSkillShellCommand` hook "can refuse a skill or command's inline shell commands as it loads".
- **Auto-updates:** on or after 30 November, plugin marketplaces in managed `extraKnownMarketplaces` auto-update by default unless set to `"autoUpdate": false`.
- **Token prefix:** self-hosted runner tokens can now start `oat02-` as well as `oat01-`. The changelog says to "update proxy rules and log scrubbers".

**Why it matters:** an MCP server used to give your agent tools whose list you could read. Now it can also send instructions and shell commands into the agent's context. A server update can change what your agent is told to do, so treat MCP config like dependencies: list which servers now expose skills, allowlist the inline shell you'll accept with the new hook, and fix your log scrubbers before a token leaks.

Source: [Claude Code changelog 2.1.331–2.1.332](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

### 3. Parallel subagents mostly buy cost, and AI reviewers aren't gates

**ACT NOW** Medium confidence.

*When Are Parallel Subagents Effective for Coding?* compared one agent with a lead agent that delegates to parallel subagents, on tasks that build whole repositories from specifications, at equal time and equal cost. Subagents raised hidden-test pass rates "by only about 1 to 5 percentage points at up to 3.8x the cost". On hard tasks, most of the gain came from things a single agent can do. One sentence telling it to probe the reference program first "recovers most of this gain at a fraction of the cost". A single agent that periodically restarts with an empty conversation progresses faster than one that resumes. A preregistered study had Claude Opus, Sonnet and Haiku 5.5 review 90 agent-written patches at three effort levels. Higher effort caught more wrong patches, but "no setting is a strong gate: each accepted at least 45% of wrong patches."

**Why it matters:** before paying for a fan-out, give one agent an explicit check-first, check-before-done step, and restart stalled sessions fresh. Use an AI reviewer to cut review load, not to approve merges. Both are preprints, the subagent tasks are greenfield builds, and the review study uses one Django dataset.

Sources: [arXiv 2611.33893](https://arxiv.org/abs/2611.33893), [arXiv 2611.33639](https://arxiv.org/abs/2611.33639)

## Signal radar

### Agents can now buy a subscription, behind a price prompt

**WATCH** Medium confidence.

From 25 November, Cloudflare's CLI and MCP servers can activate Workers Paid, R2 and Zero Trust without the dashboard. Clients that support MCP elicitation show the plan price and ask permission before activating; others are sent to the dashboard. Vercel's MCP server can now set AI Gateway routing rules and spending budgets. This is the first big platform to let an agent commit you to a recurring charge, with the approval living in the protocol. Scope agent credentials so they can't reach billing.

Sources: [Cloudflare changelog](https://developers.cloudflare.com/changelog/post/2026-11-25-activate-pay-as-you-go-cli-mcp/), [Vercel changelog](https://vercel.com/changelog/agents-can-now-manage-ai-gateway-through-vercel-mcp)

### Skills get CI gates, and the evidence that skills hurt was noise

**WATCH** Medium confidence.

NVIDIA's SkillEvaluator (Apache 2.0) checks agent skills against "500+ static rules and detection patterns" without an LLM key, ships CI templates, and then compares runs with and without a skill. An audit of the SkillsBench benchmark (arXiv 2611.33943) found grader dependence, placeholder skill folders and a harness that silently added 48 skills. After correcting for repeated tests, "no task-level reduction achieved statistical significance". Lint skills in CI, and don't drop one because a single benchmark row looks negative.

Sources: [SkillEvaluator README](https://raw.githubusercontent.com/NVIDIA/SkillEvaluator/HEAD/README.md), [arXiv 2611.33943](https://arxiv.org/abs/2611.33943)

## Research frontier

### [Letting Models Manage Their Own Context: Where We Stand](https://arxiv.org/abs/2611.34147)

**WATCH** Medium confidence. Horizon: 12 months. Affiliation not stated on the abstract page.

Most harnesses summarise history when the context window fills. Here the model gets a "context API" and decides itself when and what to compact, inside NVIDIA's open-source agent harness. At tight budgets this helped a lot: GPT 6.1 "nearly triples its score at a 32K budget". Models varied widely in how they used it, and reusing the KV cache of the unchanged part cut prefill compute by up to 15%. Compaction may become a tool the model calls rather than a fixed harness rule. Inference engines would need cheap KV-cache edits first.

### [Unlocking the Power of Loops in Pretrained LLMs with Loop Residuals](https://arxiv.org/abs/2611.31094)

**CONTEXT** Low confidence. Horizon: 12 months. National University of Singapore.

Looped transformers run a shared block of layers several times, adding compute without adding parameters. This week Z.ai's GLM-5.4 joined Thinking Machines' Inkling 2 Mini as a shipping looped model. GLM-5.4 isn't open-weight yet, according to [Simon Willison](https://simonwillison.net/2026/Nov/23/glm-54/). LoopRes retrofits loops into existing pretrained models and reports a 29.1% gain over fine-tuning alone at twice the compute on a 1.7B model, holding up to 30B. If it holds, small local coding models get better without getting bigger.

### Gate what skills can run

**ACT NOW**

Update Claude Code, check which MCP servers now expose skills, and add a `PreSkillShellCommand` hook that refuses inline shell from skills not on your list. About 30 minutes.

### Faster durable workflows

**ACT NOW**

Vercel's Workflow SDK 5.8 cut p75 step-to-step overhead from 85 ms to 7 ms, and a five-turn agent loop now adds 0.9 seconds of overhead instead of 3.0 (Vercel's own benchmarks). Runs already in flight stay on the old engine. Make steps idempotent, then upgrade. Fifteen minutes plus the idempotency check. Source: [Vercel changelog](https://vercel.com/changelog/workflows-speculative-execution)

**ACT NOW**

It's useful for agent-written code, where slow paths are easy to miss in review. About 30 minutes. ## Architecture & practice shifts

### Check first, then fan out

**ACT NOW**

Add one line to your default build-task prompt: run the tests or the reference before editing, and again before claiming done. When a long session stops improving, start a fresh one with a short hand-off note. Reach for subagents when you need modular output, not by default.

### Deterministic shell, agent core

**WATCH**

Alibaba's open-sourced Open Code Review uses plain code to pick, group and position what gets reviewed, and leaves judgement to the agent. It reports higher precision than Claude Code at about a ninth of the tokens, with lower recall (Alibaba's own benchmark). If a tool must cover every file, let code guarantee the coverage. Source: [Open Code Review README](https://raw.githubusercontent.com/alibaba/open-code-review/HEAD/README.md)

## This week's experiment

**Build:** a small A/B test of agent configurations on your own code. Pick a closed task from a repository's history whose pull request added tests. Check out the commit before it, move the new tests outside the worktree, and save the issue text as `task.md`. Run `claude -p "$(cat task.md)" --output-format json` in three setups, twice each, in fresh worktrees. A is the plain task. B adds "Before editing, run the existing tests and read how the feature is used; before finishing, run the tests again and fix failures." C is B plus "Split the work across parallel subagents where parts are independent." After each run, restore the hidden tests and run them.

**Done when:**

1. A `results.csv` has six rows with tests passed, `total_cost_usd` and `duration_ms`.
2. You can say whether B beat A, and whether C was worth its extra cost.
3. You've picked a default setup for build tasks and written down why.
4. The script runs on a second task with only `task.md` and the test path changed.
