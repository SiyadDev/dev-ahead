A busy window, nearly all of it from GitHub Universe on 28 October. This issue is about what sits under the keynote: how AI coding is billed, where agents run, and who maintains the files that steer them. One correction to issue 4: Claude Code has stopped sending the safety telemetry event that issue recommended you collect. And repeat-safety, meaning which agent actions can safely run twice, has now come up in three issues in a row. That makes it a trend.

## The top 3

### 1. GitHub turned Copilot from a seat into a metered budget, and model choice into a router

**ACT NOW** High confidence.

On 28 October GitHub said enterprises that work with a GitHub or Microsoft account team can get Copilot included with GitHub Enterprise for every licensed user. Usage is metered against an enterprise budget from the first request, with no included allowance. At zero budget, completions still work; Chat, code review and the cloud agent stop. Users without an Enterprise licence get the same access as Copilot Standalone at $10 per user per month. On the same day Copilot Fusion became generally available. You choose an effort level instead of a model, and Fusion either uses one model, cascades (a cheap model drafts, a check escalates to a stronger one if needed), or has one model critique another's draft. GitHub says Fusion Max scored 60 on the Artificial Analysis Coding Agent Index, within two points of Claude Code with Opus 5.5 Max, at about half the API cost per task. Vercel's new virtual models do the same at the gateway: agents call an alias like `vmc/coding-agent`, and you change what's behind it in one place.

**Why it matters:** AI cost is no longer a matter of which model and how many seats. It is a budget plus a routing policy. Clients can see and cap that spend, and choosing the model becomes a config setting you own. GitHub's Octoverse report says 61% of Copilot users already used more than one model in September. Treat the half-cost figure as GitHub's own until someone reproduces it independently.

Sources: [GitHub, Enterprise includes Copilot](https://github.blog/changelog/2026-10-28-github-enterprise-now-includes-access-to-github-copilot), [GitHub, Copilot Fusion GA](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion), [Vercel, virtual models](https://vercel.com/changelog/virtual-models-now-available-on-ai-gateway)

### 2. Agents moved into CI, because CI and review are now the bottleneck

**ACT NOW** High confidence.

GitHub's Octoverse post says that as of September developers start more than 40% of pull requests with an agent, up from 17% in March, and that merged pull requests more than tripled to 1.3 billion over the past twelve months. On the same day GitHub Agentic Workflows became generally available. You describe an automation in a Markdown file (issue triage, CI failure analysis, docs updates, test writing) and it compiles to ordinary Actions YAML. The agent runs read-only by default, in a sandboxed container behind a firewall. Anything it wants to write goes through "safe outputs", and a separate threat-detection job scans proposed changes before they apply. GA adds micro-VM isolation, per-workflow model choice and `gh aw forecast` for credit spend. Vercel put Vercel CI into beta the same day and said its internal wait from push to green is 2–6x shorter, so that CI can "keep up with our coding agents".

**Why it matters:** if 40% of pull requests start with an agent, the scarce resources are CI capacity and human review, not typing. GitHub's design is a good template for any agent you leave running unattended: give it read-only access, have it declare its writes, and use a separate step to check them. Budget for review time, not build time.

Sources: [GitHub, Agentic Workflows GA](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available), [GitHub, Octoverse 2026](https://github.blog/news-insights/octoverse/octoverse-commits-pushes-reach-new-highs-in-2026-as-developers-build-with-agents/), [Vercel CI beta](https://vercel.com/changelog/vercel-ci-is-now-in-beta)

### 3. Agent memory went GA, and it now proposes edits to your instruction files

**WATCH** High confidence.

Copilot Memory is now generally available on paid plans. Preferences and repository conventions carry over between sessions and across Copilot's clients. Copilot "dreaming" is in public preview: it is opt-in, costs credits, and reviews past sessions to curate memories. It also opens pull requests that change your checked-in skills and custom instruction files. GitHub's preview figure: 93% of CLI sessions that used memory followed developer preferences better. Two papers below point the other way.

**Why it matters:** files like `AGENTS.md`, `CLAUDE.md` and your skills are becoming things agents maintain, not just read. Review those pull requests as carefully as code. Give each rule a short reason, because an automated curator is more likely to drop a rule it can't explain. And measure whether memory helps your work before you pay for it.

Source: [GitHub, GitHub intelligence: Memory, dreaming and code search](https://github.blog/changelog/2026-10-28-github-intelligence-puts-your-code-context-and-history-to-work)

## Signal radar

### Repeat-safety is turning into a runtime feature

**WATCH** High confidence.

Third issue in a row. Issue 4: Claude Code retries HTTP MCP calls only for read-only or idempotent tools. Issue 5: a timed-out call now tells the model not to repeat it. Now Cloudflare Computer v0.7.0 lets agent code resume after a deploy or crash with `onInterrupt: "replay"`, reusing results it has already recorded. Cloudflare warns that a call whose result wasn't recorded may run again "even if its action already succeeded". It provides `unsafeToRepeat()` for calls that must not run twice, and `ctx.interrupt()` to pause a run for human approval. That makes three vendors working at three layers. Expect "safe to run twice?" to become a required property of tools.

Source: [Cloudflare changelog, Computer v0.7.0](https://developers.cloudflare.com/changelog/post/2026-10-26-computer-durable-javascript/)

### Harness on the host, tools in the sandbox

**WATCH** Medium confidence.

Vercel's fx adapter now runs the agent harness and model calls inside your application and keeps only filesystem and shell operations in the sandbox, so "model credentials stay on the host". Cloudflare's internal hostnames let an agent's browser open a dev server running in its container without exposing it publicly. The sandbox is shrinking to just the place where untrusted actions run, and secrets never go into it.

Sources: [Vercel, fx adapter](https://vercel.com/changelog/fx-harness-adapter-now-separates-host-and-sandbox), [Cloudflare, internal hostnames](https://developers.cloudflare.com/changelog/post/2026-10-28-browser-internal-hostnames/), [Vercel CI beta](https://vercel.com/changelog/vercel-ci-is-now-in-beta)

## Research frontier

### Memory Tax: what agent memory really costs

**ACT NOW** Medium confidence. Horizon: already shipping. University of Illinois Urbana-Champaign.

[arXiv 2610.34073](https://arxiv.org/abs/2610.34073). The authors compared dedicated agent-memory systems with naive retrieval over the raw history, across several benchmarks and models, and found that many memory systems did worse. They split memory's net value into a benefit and a "tax". The tax is what you lose when the memory step reorganises or summarises history and drops evidence a later task needed.

**Why it matters:** before you turn on any memory layer, compare it with plain retrieval over your transcripts, on your own tasks. Connects to the **Context engineering** entry on the Watch board; no status change.

### Skills that help strong models can hurt weak ones

**WATCH** Medium confidence. Horizon: 12 months. University of Chinese Academy of Sciences.

[arXiv 2610.33024](https://arxiv.org/abs/2610.33024). Submitted on 10 October and featured on Hugging Face Daily Papers on 27 October. Across 103 task-skill pairs, the same skills raised GPT-5.6 Luna's score by 31.1 points and lowered Gemma-4-E4B's by 8.8. In 86% of the weaker model's failures, the rule it broke was already written in the skill. The fix is a fixed "meta-skill" that guides rewriting each skill for the model that will run it. It improved the weaker models by 5.1 to 14.1 points. The institution comes from the Hugging Face listing.

**Why it matters:** a skill file can run anywhere, but its effect depends on the model running it. If you route work to cheaper models, test your skills on those models too. Connects to **Portable agent skills**; no status change.

### Benchmarking the harness, not the model

**WATCH** Medium confidence. Horizon: 12 months. TraceLite AI.

[arXiv 2610.32285](https://arxiv.org/abs/2610.32285). TraceTrial-Bench has 95 expert tasks covering seven areas of harness behaviour: context, execution, governance, lifecycle, observability, tools and verification. The authors ran 3,420 runs across 4 harnesses and 9 models. Harness scores ranged from 59.8% to 72.0%, and 31.1% of runs completed the task while breaking at least one harness rule. The institution comes from the Hugging Face listing.

**Why it matters:** "the task succeeded" and "the agent behaved" are separate measurements. Test your guards separately from the output. Connects to **Harness layer**; no status change.

## Architecture & practice shifts

### Read-only agent, declared writes, separate checker

**ACT NOW**

On Monday, take one agent job you run on a schedule and split it in two: the agent decides with read-only access, and a separate step validates and applies its declared writes.

### Mark every tool's repeat behaviour

**ACT NOW**

For every tool your agents call, write down whether it is read-only, idempotent or unsafe to repeat. Then encode that in MCP annotations, an idempotency key or a runtime flag.

## This week's experiment

Give an unattended agent a failure contract. 60–90 minutes.

**Build:** in a repository with a CI job, install the `gh aw` extension using GitHub's quickstart and add a CI-failure-analysis workflow, either from GitHub Next's agentics repository or with `gh aw add-wizard`. Run `gh aw forecast`, then break a test on a branch and push.

**Done when:**

1. The Markdown workflow and its compiled Actions YAML are committed.
2. A deliberately failing CI run triggers the workflow, and it posts its diagnosis through a safe output (a PR comment) rather than writing directly.
3. You have confirmed from the workflow's permissions that the agent job is read-only.
4. You have re-run the same failed job and noted whether it posts a second comment. That is your repeat-safety answer.
5. One line compares the forecast with the credits actually spent.
